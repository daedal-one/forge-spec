# Session token design

Internal design notes for the session token format and lifecycle.

## Token shape

Tokens are opaque 256-bit values, base64url-encoded. They are
generated by the auth service and never reused.

## Credential rotation

When a user rotates credentials (password change, MFA reset),
all existing session tokens for that user MUST be invalidated.
This drives clause `timeout-policy.3` of the session expiry
requirement.

The rotation flow:
1. Auth service receives credential change
2. Lookup all active sessions by user_id
3. Delete each session key from Redis (does not wait for TTL)
4. Emit `session.revoked` event for downstream consumers

## Observability

Each invalidation emits a structured log line. See the
[observability spec](spec:REQ:infra/observability) for the
schema.
